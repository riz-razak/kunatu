Claude Design should run after the RainViewer/MapLibre build is deployed or at least locally verified. The design review should evaluate a real radar surface, not the old placeholder.

## Review Rounds

1. UI review: Bawa Earth compliance, hierarchy, color, spacing, map treatment.
2. UI review: component detail for hero, guidance cards, forecast strip, radar controls, admin shell.
3. UI review: CMS/translation surface and copy-key visibility.
4. UX review: public user journey from open page to practical decision.
5. UX review: admin/editor journey and auth.yan readiness.
6. Stress test: mobile low-end screen.
7. Stress test: Sinhala/Tamil text expansion.
8. Stress test: trust/safety and official-warning boundaries.

## Design Questions

- Does the page answer what users should plan around in the next few hours?
- Does the radar map feel like real weather context without overpowering guidance?
- Are observed radar and short-term projection labels clear?
- Are practical suggestions useful without sounding cute or alarmist?
- Does the admin scaffold look auth-ready without pretending to be protected before auth.yan is wired?

## Output

Claude Design should produce:

1. Homepage visual revision notes.
2. Radar map/control refinements.
3. Mobile layout fixes.
4. CMS/admin surface refinements.
5. Copy and translation key changes.
6. A short implementation checklist for the next engineering pass.
